# Lunarpc Test Suite

This book is the **internal test reference** for lunarpc. It is generated
from OCaml expect tests via [mdexp](https://github.com/mbarbin/mdexp) and is
meant to be browsed alongside the source code.

## Who is this for?

The audience is **developers and agents working on the system** --- not end
users. If you are looking for user-facing documentation, see the
[main documentation site](../doc/).

## Why a book?

Good tests accumulate an excruciating level of detail: edge cases, error
paths, protocol exchanges, and internal invariants. Presenting them as a
structured book carries real value: it enables high-level thinking,
navigation between related areas, and a coherent organization that flat test
files alone cannot provide.

The book format makes it possible to skim a chapter to understand a
subsystem's behavior, then drill into individual sections when debugging or
extending it.

## How does it relate to the user documentation?

There is inevitable overlap between this test book and the documentation in
`doc/`. The key difference is intent:

- **`doc/`** is focused on the **user experience** --- how to install,
  configure, and use lunarpc. It omits low-level details.
- **`test/`** is focused on **correctness** --- every RPC, every error case,
  every CLI invocation. It includes details that would overwhelm a user guide
  but are essential for someone modifying the code.

When both cover the same topic, the doc version explains *what to do* while
the test version proves *that it works*.

## Structure

Each test file is an OCaml module with `@mdexp` directives that mark prose
sections and snapshot captures. Running `mdexp pp` on the source extracts
those into the markdown you are reading now. Because the source is compiled
and tested on every build, the documentation cannot drift from the
implementation.

- **Stdlib** --- unit tests for `lunarpc-stdlib` itself.
- **Rpc** --- unit tests for the `lunarpc` core library, one
  `test__$FILE.md` chapter per source file, each function under test getting
  its own section.
- **Keyval** --- an end-to-end example RPC client/server, used to exercise
  the `lunarpc-client`, `lunarpc-server`, `lunarpc-discovery`, and
  `lunarpc-test-harness` libraries via a small CLI.

## Building

The markdown files are regenerated by running:

```bash
dune runtest
```

To browse this book locally:

```bash
cd test && mdbook serve --open
```
